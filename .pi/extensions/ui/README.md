# ui

Interface-only extension. Run `/reload` to load it.

- **Ctrl+C** saves nonempty editor text into Up-arrow prompt history before Pi clears it. Large paste markers are expanded. Nothing is submitted to the agent or added to the conversation. Native clear/exit behavior remains unchanged, and dialogs are unaffected. Also follows a remapped `app.clear` binding.
- **Compact tools** are enabled by default. No colored panels, output, diffs, or inline images: one summary line per tool, with blue/theme-link-colored tool names, slightly emphasized teal file basenames, and muted grey directories, line ranges, arguments, and summaries. Bash shows `$ command` with shell syntax highlighting (strings, variables, keywords, and comments), blended toward muted grey. Bash command names (argv0) use the same muted teal accent, including commands after pipes, `&&`, and semicolons. The display-only lexer skips assignment prefixes, redirection targets, quoted arguments, and comments; it is conservative around heredocs and does not resolve expansions. Multiline commands remain on one display line. In compact view, codemode shows its label with nested tool calls underneath using the same compact styling. Consecutive file calls are grouped, so file paths appear at a second indentation level. Live calls use their full arguments and results for summaries; restored sessions fall back to saved argument previews (truncated previews may lack file ranges). `/ui compact-code` additionally displays the script with subdued JavaScript syntax highlighting, including raw and `{ code }` inputs. Short scripts that fit stay beside the tool name; multiline or longer scripts appear underneath, indented like grouped reads, preserving JavaScript newlines and indentation and wrapping long lines to the terminal width. Highlighting follows the active theme; native collapsed/expanded renderers are unchanged. Consecutive reads, writes, or edits of the same tool are grouped under one heading with indented file paths. One blank line separates tools/groups. Running and failed calls retain a small status marker.
- **Line ranges** follow paths: `read a.ts:10-34`, `write a.ts:1-20`, `edit a.ts:5,20-22`. Reads use the requested offset/limit, or returned line count for full reads. Writes use content line count. Edits use changed-line numbers from the result diff; differing old/new spans are labeled, e.g. `a.ts:old 10-11 → new 10-12`. Unknown ranges are omitted; no extra file reads are performed.
- **Ctrl+O** cycles **compact → compact-code → collapsed → expanded → compact** in the main editor, also following a remapped `app.tools.expand` binding. Each key press advances once; Kitty key-release events and held-key repeats do not advance the cycle. Dialog/overlay shortcuts and explicit history bindings retain their native behavior. **Ctrl+Alt+O** remains a direct compact/normal toggle. Commands: `/ui compact`, `/ui compact-code`, `/ui collapsed`, `/ui expanded`, `/ui normal`, `/ui toggle`, `/ui cycle`. Each change uses Pi’s in-conversation `Tool output: <mode>` status notice for all four modes, updating consecutive notices in place. There is no footer mode label. View preference is saved in the session.

Normal view uses Pi's original rendering, including renderers supplied by other extensions. No tool execution, parameters, results, or model context are changed. Non-TUI modes are untouched.

## Compatibility

Pi has no public transcript grouping/spacing API. `compact.ts` therefore wraps component **instances**, not global prototypes, and recognizes Pi's `ToolExecutionComponent` runtime fields. The Ctrl+C and tool-cycle listener uses the main `CustomEditor`'s action map/keybindings to distinguish editor actions from dialog/overlay input. The tool-cycle action (including repeat reports) is consumed before Pi's two-state toggle runs. Raw listeners run before Pi's key-release filtering, so this extension explicitly ignores release reports. All wrappers/listeners are removed on reload/shutdown. A future Pi change to these internals may require updating the adapter; unrecognized components keep their normal rendering. Other main editors work if they preserve CustomEditor's action map and history interface.
